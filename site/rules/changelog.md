# 评分规则表

`official-rule.json` 是评分的唯一规则来源。`site/assets/app.js` 启动时读它，
读不到文件就用内置兜底（并在评分卡上写明「内置兜底」），**文件存在但内容不合法时整站拒绝启动**——
静默退回另一套曲线，比不评分更糟。

改这张表不需要动代码：`domain/scoring.js` 的计算式与这张表解耦，
`tests/rules.test.js` 会钉住「换了表，分数必须跟着变」。

## 哪些是真实的，哪些是占位的

| 字段 | 状态 | 依据 |
|---|---|---|
| `weights` | 真实 | 官网口径：病史10 · 体格10 · 辅助70 · 诊断10 · 治疗0 |
| `excess.from/to` | 真实 | `reasonable`/`max` 两档阈值由再生脚本从官网数据带出，存在 `data/cases.json` 的 `limits` |
| `excess.maxFraction` | **占位** | 官网未公开「到上限扣满多少」 |
| `excess` 的形状 | **占位** | 目前为合理线→上限的线性加重；官网曲线未知 |
| `overdiagnosis.perItem` | **占位** | 目前每写一个标准答案里没有的诊断，扣掉诊断模块的 25% |
| `combine` | 设计决定 | 同一模块的「次数超」与「花费超」取最重一条，不叠加 |
| `evidence.weight` | 真实为 0 | 证据判读（支持/不支持）作为独立维度展示，官网不给分 |

**阈值不在这张表里。** 每个病例的 `standard/reasonable/max` 随病例存在 `data/cases.json`，
规则表只放与病例无关的曲线形状——同一个数有两处来源一定会漂。

## 实测官网后要做的事

1. 在同一份答卷上记录官网给出的扣分数，反推曲线（至少取三个点：刚过合理线、中点、到上限）。
2. 改 `official-rule.json`，把 `status` 从 `placeholder-curve` 改成 `measured`，`ruleVersion` 递增。
3. 在下面的版本记录里加一行，写清测的是哪个病例、哪个科室页面、日期。
4. `npm test` —— 结构校验与「换表分数必变」两条会重新钉住。
