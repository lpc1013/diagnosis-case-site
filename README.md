# 诊断学临床思维训练 · 答案对照站

一个静态、零依赖的单页应用，用于对照「临床思维训练系统」整体思维训练 4 例病例的
标准答案，并在本地做闭卷练习与评分。三档信息密度（**学习**全对照 / **考试**零提示 /
**复盘**看临床思维链）、百分制评分 + 超额扣分 + 提交锁定、移动端适配与本地进度持久化。

> 本项目为个人学习用途。校内系统的账号、密码与内网端点等凭据**不在此仓库中**，
> 相关爬虫与运维脚本亦已排除，请勿在公开场合分享。

## 目录结构

```
site/
  index.html               入口页（<script type="module">）
  serve.js                 零依赖本地静态服务器（默认只监听 127.0.0.1，响应带 CSP）
  assets/
    app.js                 UI 与交互（ES Module）
    qa.js                  行为级自测驱动：URL 不带 #qa= 时整模块不做事
    style.css              样式
    js/
      package.json         {"type":"module"}，让 Node 也按 ESM 载入这一子树
      domain/
        case.js            键生成与条目枚举（渲染/评分/持久化共用同一份键）
        scoring.js         评分引擎（纯函数：病例 + 答卷 + 规则表）
        answer.js          应用状态 → 单份答卷的投影
        interview-engine.js 临床问诊时间序列：增量重放 + 问诊路径（前端与构建脚本共用）
        reasoning.js       临床思维链：线索 → 假设 → 证据 → 排除 → 确定（纯函数）
      data/
        schema.js          病例结构校验 + 加载失败分类
        persistence.js     localStorage 读写、版本迁移、脏数据丢弃
        case-registry.js   病例 ↔ 原始导出文件的配对（按内容，不按目录顺序）
  rules/
    official-rule.json     评分规则表（曲线形状仍是占位，见「评分规则」）
    changelog.md           规则版本记录
  data/
    history_records.json   病史重放数据（再生数据，未纳入版本库）
    cases.json / diaglib.json  大体量生成数据，见「数据再生」
tests/                     node:test 回归套件（118 项）
tools/
  qa_run.js                行为级 E2E：起服务器 → 无头 Chrome 跑三趟 → 按退出码判定
  qa_parse.js              dump-dom 结果解析（单独成模块，好被测试直接喂假 DOM 证伪）
  shot.js                  三档信息密度的无头截图取证 → _qa/ui-*.png
build_site_data.js         生成 cases.json / diaglib.json
build_history_records.js   生成 history_records.json
```

## 本地运行

```bash
node site/serve.js         # http://127.0.0.1:8787 ，PORT/HOST 可覆盖
npm start                  # 同上
npm test                   # 单元与静态回归（118 项）
npm run test:e2e           # 行为级 E2E（需要本机有 Chrome/Edge，或设 CHROME_PATH）
```

前端是 ES Module，必须经 HTTP 打开，`file://` 直接双击会被浏览器的模块跨域策略拦住；
页面会把这种失败单独识别为 `NETWORK_ERROR` 并说明原因。

## 三档信息密度

顶栏三档不是三套皮肤，是三种**信息可见性**，共用同一份评分与同一份答卷数据：

| 档 | 能作答 | 能看到什么 | 看不到什么 |
|---|---|---|---|
| 学习 | 否 | 全部标准答案：必要项、分值、三层对照、系统完整检查记录 | — |
| 考试 | 是（提交后锁定） | 只有题目与自己的选择；限额进度条 | 任何「必要 / 分值 / 含正确选项 / 标准结果」 |
| 复盘 | 否 | 提交后：自己的作答与标准答案并排 + 扣分明细 + **临床思维链** | 未提交时不开答案（只说明为什么不开） |

- 提交后自动进入复盘档；「重新练习本病例」会退回考试档。
- 档位是**会话级**视图选择，不进 localStorage：刷新回到考试档，避免把「上次在看学习档」
  当成学生的作答意图，也让行为级 E2E 的起点可预期。
- 考试档零泄露、复盘档不开答案这两件事由行为级 E2E 逐板块扫 DOM 证明（见下节），
  并且配了一条反向断言（学习档必须真的能扫到答案节点），否则「零泄露」是永真绿。

### 临床思维链

复盘档右栏把答卷还原成五段轨迹：发现线索 → 提出假设 → 寻找证据 → 排除 / 待排 → 确定诊断。
数据来自 `interview-engine`（问了哪一步、那一步得到哪几行记录）与 `reasoning`
（假设与标准依据树的逐条对账），显示层不自己数：

- 线索段带问诊覆盖率（`问诊 26/37 步（跳过 11），得到检查记录 34 行`）；
- 假设段按**学生添加的顺序**排，同义名会归位到标准诊断；
- 证据段报「落在标准依据树几条 / 判读命中率」，口径与评分侧 `evidenceReview` 同一份实现；
- 排除段既列「标准答案中没有」（过度诊断），也点名**思维自相矛盾**：
  列为主要诊断、却不支持证据标得比支持证据多；
- 确定段列出漏诊。

思维链**不参与计分**，只还原路径；评分口径的唯一来源仍是规则表。

## 测试

`npm test` 只依赖 Node 内置的 `node:test`（建议 Node ≥ 22.12）。
其中「真实四例」相关用例会自动跳过，直到你按下面的步骤生成 `site/data/cases.json`。

覆盖的回归点：静态服务器的目录越界与非法 URL、CSP 与内联脚本、评分覆盖与超额扣分、
惩罚明细与实扣金额对账、规则表换数分数必变、成绩单与病例/规则版本绑定、
诊断分类持久化与未分类语义、治疗场景持久化、跨档筛选不穿透、病史/治疗条目键唯一性、
重放内容与终态一致、问诊路径逐句对账、临床思维链与评分共用同一份匹配与判读、
病例配对不受文件顺序影响、本地存储的版本迁移与脏数据丢弃、
样式表括号逐层闭合与「画出来的类名都有样式」、三档接线的静态一致性。

`npm run test:e2e`（`tools/qa_run.js`）跑的是**用户那条链**：自己起服务器，用同一个无头
profile 跑三趟壳页——

1. `#qa=act`：打开病例 → 逐板块点到标准线 → 辅助两组全选并检测 → 诊断搜索+添加+分类 →
   治疗选场景并点项（含「切换场景」这个曾经点不动的控件）→ 提交，
   把成绩单**与答卷本体快照**写进 localStorage；
2. `#qa=density`：三档信息密度的可见性取证（考试档**逐板块扫全部可见条目行**确认零泄露、
   复盘档思维链五段 + 线索段确实接上真实问诊轨迹、学习档反证、
   未提交病例上复盘不开答案）；
3. `#qa=verify`：重新载入 → 读回成绩单**和答卷本体**（各板块计数、已采集项数、
   每个诊断的分类与证据标记、治疗场景）→ 逐项比对 → 再点一次确认锁定。

第 3 步为什么要读答卷而不是只读成绩单：成绩单是提交那一刻算完就存下的快照，
「刷新后存档把分类丢了」这种漂移会表现为「分数一模一样」而悄悄溜过去——
这一条是实测复现过的，不是设想。

**每条新闸都要求自报命中数并至少灌一次缺陷证伪**（`_qa/` 下的临时脚本用完即删）；
已揪出的假绿包括：解析器把 `pass:'false'` 判成通过、辅助只跑 1 组、诊断只加 1 个、
进入辅助板块折叠导致「零泄露」对着空表断言、分类快照两边都读成「未分类」。

`node tools/shot.js` 产出 `_qa/ui-{exam,study,review}.png`，用于肉眼验收三档画面。

## 数据再生

`site/data/cases.json`（约 8MB，4 例完整数据）与 `diaglib.json`（约 1.5MB，诊断库）
体积过大且属于再生数据，不纳入版本库；`history_records.json` 同理。
需要本地跑完整站点时，用私有爬虫与构建脚本再生：

```bash
node build_site_data.js          # 读 overall_cases/ 与 recon/，写 cases.json + diaglib.json
node build_history_records.js    # 读 recon/incr_c*.json，写 history_records.json
```

两个脚本都会**先自检再落盘**：

- `build_site_data.js` 写出前用前端同一份 `schema.js` 校验；出现 error 即中止，不产出文件。
- `build_history_records.js` 比较「重放全部步骤」与终态记录；内容不一致即抛错中止。
- 病例与原始导出按 `meta.name` 配对，配不上或出现同名/多余文件都会报错——
  不再依赖目录枚举顺序（顺序变了会静默串病例）。

## 评分规则

百分制，权重沿用官网口径：**病史 10% · 体格 10% · 辅助 70% · 诊断 10% · 治疗 0%**
（治疗不计入满分门槛）。

```
S = Σ  weight_m × clamp( 必要项覆盖率_m × (1 − 超额惩罚_m) )
```

- `limits` 里的 `standard / reasonable / max`（以及辅助的 `costStandard/costReasonable/costMax`）
  直接来自官网导出的真实阈值：`reasonable = standard × 1.5`、`max = standard × 2`。
- 进度条与评分**共用同一份统计**（`limitMetrics`）：超过扣分线一定会在分数上体现，
  评分卡逐条列出「哪个模块、哪条指标、实际值、扣分线、扣了多少分」。
- 同一模块的次数惩罚与花费惩罚**取最重一条，不叠加**。
- 多写一个本病例标准答案里没有的诊断 = 过度诊断，按诊断模块折算扣分。
- 诊断**不分类就是未分类**：站点不再把「主要诊断」当默认值塞给学生，未分类会扣分并列出清单。
- 证据「支持/不支持」判读目前作为**独立维度输出**（显示命中率），不计入总分。

### ⚠ 扣分曲线是占位实现

官网只导出了阈值（标准线/扣分线/上限），**没有导出「超过扣分线后每超一项扣几分」的曲线**。
现实现为线性：`惩罚 = clamp((实际值 − reasonable) / (max − reasonable), 0, 1)`，
到硬上限时该模块按 0 折算。这条线性形状是**站点自定义的假设**，不是官网公式——
规则表里 `status: "placeholder-curve"` 就是把它写在数据里，评分卡也会显式说明。

实测到真实曲线后**只改 `site/rules/official-rule.json`**（`excess.maxFraction` /
`overdiagnosis.perItem` / `combine`，并把 `status` 改成 `measured`、递增 `ruleVersion`、
在 `site/rules/changelog.md` 记一行测量依据）。`domain/scoring.js` 的计算式与调用方都不用动；
`tests/rules.test.js` 里的「换这张表，分数必须跟着变」会守住这个边界。
规则文件缺失时页面按内置兜底打分并在评分卡写明来源；**文件存在但内容不合法则整站拒绝启动**
（静默退回另一套曲线比不评分更糟）。

一个已经用真实数据验证过的性质：**只选全部必要项时四例均为 100 分**
（各板块必要项数量都 ≤ 官网 standard 或 ≤ reasonable），所以占位曲线不会冤枉「精准作答」。

## 已知限制

- 数据再生依赖私有爬虫（源系统与 `recon/` 增量导出不在仓库内）。
- 扣分曲线是占位假设，需实测官网才能定稿（见上节）。
- 考试档的选项提交后不可撤销，复盘档不可改作答，这是模拟考试语义下的有意设计。
- 档位（学习/考试/复盘）是会话级视图选择，不持久化；病例进度与成绩持久化。
- `history_records.json` 中 case1 为「终态比例还原」的估算轨迹，页面会明确标注它仅用于演示。
- 移动端报告抽屉在关闭时对整个面板置 `inert`；窄屏判定用 `max-width: 860px`。
- ≥861px 时左侧病例栏是浮层抽屉，展开时会盖住作答区左半边（v50 的既有交互，未在本轮改动）。
